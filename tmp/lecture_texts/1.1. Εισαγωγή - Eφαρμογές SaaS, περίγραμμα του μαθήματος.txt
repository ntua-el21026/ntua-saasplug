Εαρινό εξάµηνο 2025-2026
Περιγραφή
Η εργασία αφορά την ανάπτυξη του δικτυακού λογισµικού saasPlug, το οποίο είναι µια υπηρεσία που επιτρέπει
σε χρήστες ηλεκτρικών οχηµάτων να βρίσκουν και να κάνουν κρατήσεις φορτιστών από οποιονδήποτε πάροχο.
Ο κύκλος της ανάπτυξης δεν περιλαµβάνει καθορισµό και προδιαγραφή απαιτήσεων, αλλά επιχειρεί να
προσοµοιώσει συνθήκες όπου στην πορεία της ανάπτυξης µιας εφαρµογής, απαιτήσεις που είναι σε κάποιο
αρχικό βαθµό καθορισµένες, εξειδικεύονται από την κάθε οµάδα. Οι αρχικές αυτές απαιτήσεις δίνονται από τους
διδάσκοντες σε µορφή ενός περιληπτικού εγγράφου SRS. Η εργασία εστιάζει στην αρχιτεκτονική, τις τεχνολογίες
και τα σύγχρονα εργαλεία ανάπτυξης εφαρµογών που παρέχονται ως υπηρεσία, συµπεριλαµβανοµένων
επιλεγµένων εργαλείων AI, καθώς και στην εφαρµογή ευέλικτων µεθοδολογιών ανάπτυξης.
Το saasPlug είναι µια δικτυακή υπηρεσία που απευθύνεται σε παρόχους υποδοµών φόρτισης, ένας εκ των
οποίων θα µπορούσε να είναι ο λειτουργός κάθε εφαρµογής που αναπτύχθηκε στο θέµα εξαµήνου του
µαθήµατος "Τεχνολογία Λογισµικού" κατά το τρέχον ακαδηµαϊκό έτος. Κάθε τέτοιος πάροχος σήµερα
επιβαρύνεται µε το κόστος της ανάπτυξης και λειτουργίας της δικής του δικτυακής εφαρµογής ενηµέρωσης των
πελατών του - χρηστών των σηµείων φόρτισης που προσφέρει. Το λογισµικό saasPlug θα του παρέχεται ως
υπηρεσία (SaaS) η οποία θα του επιτρέπει να καταργήσει τη δική του εφαρµογή και να παρέχει ενηµέρωση στους
πελάτες του µέσω αυτού. Μοναδική απαίτηση από τον πάροχο θα είναι η παροχή στο saasPlug πρόσβασης στην
προγραµµατιστική διεπαφή (API) των φορτιστών του.
Οι πάροχοι υποδοµών φόρτισης ωφελούνται από τη λειτουργία του saasPlug όχι µόνο επειδή ελαχιστοποιείται
ή µηδενίζεται η ανάγκη να συντηρούν δικές τους εφαρµογές που απευθύνονται στους πελάτες τους, αλλά και γιατί
µε τους χρήστες ηλεκτρικών οχηµάτων να αποκτούν µιας-στάσης πρόσβαση σε πληροφορίες φορτιστών,
διευκολύνεται η διεύρυνση της συγκεκριµένης αγοράς, πράγµα καλό για όλους. Το saasPlug θα είναι δωρεάν για
χρήστες οχηµάτων και θα χρεώνεται ως υπηρεσία στους πάροχους υποδοµών φόρτισης.
Οι ελάχιστες υποστηριζόµενες λειτουργίες θα είναι οι ακόλουθες:
• Login χρηστών ηλεκτρικών οχηµάτων µε Google (*)
• Επισκόπηση / αναζήτηση σηµείων φόρτισης από χρήστες ηλεκτρικών οχηµάτων
• Κράτηση σηµείου φόρτισης από χρήστες ηλεκτρικών οχηµάτων
• Εγγραφή παρόχου υποδοµών φόρτισης
• Θέαση στατιστικών / analytics παρόχου
• Θέαση τιµολογίου χρήσης του saasPlug προς παρόχους
• Πληρωµή τιµολογίου χρήσης του saasPlug από παρόχους (*)
• Εξαγωγή (export) δεδοµένων χρήσης του saasPlud από παρόχους (*)
• Θέαση καθολικών στατιστικών / analytics από τον χειριστή του smartPlug
(*) Οµάδες 5 - 6 ατόµων
Οι λειτουργίες αυτές περιγράφονται ως περιπτώσεις χρήσης οι οποίες περιέχονται σε έγγραφο SRS που δίνεται
στο Helios και µπορεί να συµπληρωθούν ή/και να εξειδικευτούν.
Οµάδες, εργαλεία
Η εργασία θα γίνει από οµάδες των 3-6 ατόµων. Η ανάπτυξη θα έχει ως αποτέλεσµα µια διαδικτυακή εφαρµογή
η οποία θα πρέπει να τρέχει σε περιβάλλον Docker containers. Με την οριστικοποίηση των οµάδων θα διατεθούν
από τους διδάσκοντες τα αντίστοιχα GitHub repositories.

===== PAGE 2/2 =====
Η αρχιτεκτονική της εφαρµογής είναι (υποχρεωτικά) η αρχιτεκτονική microservices. Τα εργαλεία που θα
χρησιµοποιηθούν έχουν ως ακολούθως:
● Σχεδίαση, αρχιτεκτονική: Visual Paradigm ή PlantUML, PlantUML-VP plugin.
● Υλοποίηση: js, Python, React ή άλλο framework για frontend. DBMS επιλογής σας.
● Διαχείριση πηγαίου κώδικα: GitHub
● Διαχείριση έργου: GitHub
● Deployment: Docker containers
● AI: Συγκεκριµένα µοντέλα µε το εργαλείο ailog
Παραδοτέα
Τα παραδοτέα της εργασίας έχουν ως εξής:
1. Μοντέλο UML σε Visual Paradigm ή PlantUML που περιλαµβάνει: διαγράµµατα UML use case, activity,
class, component, deployment και sequence, καθώς και σχεδίαση δεδοµένων (ER ή διάγραµµα
κλάσεων). Το µοντέλο κλάσεων θα περιγράφει τους τύπους δεδοµένων που ανταλλάσσονται (πχ json
objects), καθώς και τα APIs που θα υλοποιηθούν. Σε καθένα από τα components θα πρέπει να υπάρχει
αναφορά στον αντίστοιχο πηγαίο κώδικα στο GitHub. Το µοντέλο UML θα πρέπει να είναι συνεπές,
δηλαδή οι λειτουργίες και τα δεδοµένα που ανταλλάσσονται θα πρέπει να αναφέρονται µε τα ίδια
ονόµατα συστατικών, λειτουργιών ή τύπων σε όλα τα διαγράµµατα, ανεξάρτητα από το αν
χρησιµοποιήθηκε Visual Paradigm ή PlantUML. Το deployment model πρέπει να περιέχει ports και να
περιγράφει πλήρως τη χρήση docker. Σε περίπτωση χρήσης PlantUML θα πρέπει όλα τα διαγράµµατα
να οργανωθούν σε ένα αρχείο markup (.md), ενώ ισχύει η ίδια απαίτηση συνέπειας των διαγραµµάτων.
2. Github repository µε τον πηγαίο κώδικα, συµπεριλαµβανοµένων deployment scripts.
3. Η εφαρµογή σε λειτουργία σε docker containers. Προαιρετικά µπορείτε να ανεβάσετε την εφαρµογή σε
υποδοµή cloud της επιλογής σας. Θα γίνει προσπάθεια να σας διατεθεί εικονική µηχανή στην οποία να
τρέξει η εφαρµογή σας.
4. Project στο GitHub µε την πορεία διαχείρισης / εκτέλεσης του έργου µε 2-3 sprints
5. Τεκµηρίωση χρήσης εργαλείων AI (non-binary grading)
